# Volkswagen Carnet Docker sandbox

This directory is a small, isolated test environment for debugging the
`volkswagencarnet` authentication flow without installing Python or any Python
modules on the Docker host.

Only Docker / Docker Compose are required on the server.

## 1. Configure credentials

From the repository root:

```bash
cd sandbox
cp .env.example .env
nano .env
```

Set `VW_USERNAME`, `VW_PASSWORD`, and (if needed) `VW_COUNTRY`.

The real `.env` file is ignored by git. Do not commit credentials.

## 2. Build

```bash
docker compose build
```

All Python dependencies are installed inside the image.

## 3. Test authentication

```bash
docker compose run --rm vw-sandbox
```

For detailed authentication logging:

```bash
docker compose run --rm vw-sandbox --debug
```

Try several login attempts:

```bash
docker compose run --rm vw-sandbox --debug --tries 3
```

Test login and then fetch/update vehicle data:

```bash
docker compose run --rm vw-sandbox --debug --update
```

## Development workflow

The repository is mounted into the container at `/workspace`. Python starts
with `/workspace` as its working directory, so changes made to
`volkswagencarnet/` in your checkout are picked up on the next run.

You normally only need to rebuild the image when dependencies or packaging
files change:

```bash
docker compose build
```

For ordinary Python code changes, just rerun:

```bash
docker compose run --rm vw-sandbox --debug
```

## Authentication diagnostics

The sandbox passes the fork's authentication diagnostic options to
`Connection`:

- `sandbox/state/auth_cookies.json` - persisted authentication cookie state,
  if the library writes it.
- `sandbox/debug/` - authentication debug dumps generated by the library.
- `VW_FAKE_USER_AGENT=true` - enables the fork's fake-user-agent option.

Both `state/` and `debug/` are ignored by git.

If you want a completely clean authentication attempt:

```bash
rm -rf state debug
docker compose run --rm vw-sandbox --debug
```

## Shell inside the sandbox

For ad-hoc testing without installing anything on the host:

```bash
docker compose run --rm --entrypoint /bin/bash vw-sandbox
```

Then, inside the container:

```bash
python
pytest
```

Note: the image installs runtime dependencies only. If you also want `pytest`
and the repository's test tooling inside the image, we can add a separate test
target/profile.
